# repos

Сюда `mise run clone` клонирует шаблоны из организации hexlet-boilerplates. Каталог в `.gitignore`, отслеживается только этот файл.

У каждого клона свой `.git`, своя ветка и свой `AGENTS.md`, если он у шаблона есть. Правки клонов коммитятся в их репозиториях.

## Какие репозитории клонируются

Выбор задаёт регулярное выражение `GHORG_MATCH_REGEX` в `.ghorg.conf.yaml`.

| Клон | Стек |
| --- | --- |
| `nodejs-package` | пакет для Node.js на JavaScript |
| `typescript-package` | пакет на TypeScript |
| `vite-package` | пакет на Vite |
| `fastify-api-application` | API-приложение на Fastify |

## Как это работает

Клонирует ghorg, он выбирает репозитории организации по имени. Повторный `mise run clone` подтягивает уже существующие клоны. Флаг `GHORG_NO_CLEAN: true` в конфиге запрещает ему делать `git clean`, иначе неоформленные правки в клонах пропали бы без предупреждения.

Версия клона равна моменту клонирования или последнего обновления. Фиксировать коммиты ghorg не умеет, для этого нужны submodules или манифест с хешами (причина выбора в [ADR 0001](../docs/adr/0001-clones-via-ghorg-not-submodules.md)).

Каталог должен оставаться пустым до первого клонирования, потому что `git clone` не пишет в непустой каталог. Поэтому здесь только этот README, а клоны лежат рядом с ним.

## Что здесь запрещено

Не запускай `ghorg clone` без `--no-clean` и не снимай флаг в конфиге. Не создавай файлы в `repos/` руками, всё содержимое приходит из клонирования.
