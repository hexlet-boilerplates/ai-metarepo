# Шаблоны подключаются клонами через ghorg, а не submodules

Шаблоны из hexlet-boilerplates клонируются в `repos/` командой `mise run clone`, которая вызывает ghorg. Каталог `repos/` лежит в `.gitignore`, метарепозиторий не хранит ни коммиты клонов, ни ссылки на них. Версия клона равна моменту клонирования.

## Considered Options

**Git submodules.** Фиксируют коммит каждого клона в метарепозитории и дают воспроизводимую пару «спека плюс код». Отвергнуты для этой демонстрации, потому что она работает с живыми шаблонами на `main`, а не со снимком релиза. Submodule после `git submodule update` оказывается в detached HEAD, забытый push подмодуля оставляет метарепозиторий ссылаться на коммит, которого нет на сервере, а `git status` в корне показывает изменения клонов в виде «modified content». Для агента всё это лишние поводы ошибиться.

**Манифест с хешами коммитов** (как у Google `repo` и Zephyr `west`). Даёт воспроизводимость без submodules, но требует отдельного формата, инструмента и процесса обновления хешей. Для демонстрации из четырёх клонов цена выше пользы.

**Родительский каталог без git.** Проще всего, но правила и спеки нигде не хранятся, и общие документы теряют историю.

**ghorg с `--no-clean` (выбрано).** Выбирает репозитории организации по имени, ставит и подтягивает клоны одной командой. Версий не фиксирует.

## Consequences

- Воспроизводимости по коммитам нет. Если она понадобится, решение пересматривается в пользу манифеста или submodules.
- По умолчанию повторный `ghorg clone` делает `git pull` и `git clean` в каждом клоне и стирает неоформленные правки. Поэтому `GHORG_NO_CLEAN: true` обязателен и закреплён в `.ghorg.conf.yaml`.
- Агента нельзя просить «обновить клоны» произвольной командой. Обновление идёт задачами `mise run clone` и `mise run pull`.
- Метарепозиторий не знает, на какой ветке клон. Ветку проверяет `mise run status` и правило в `AGENTS.md`.
