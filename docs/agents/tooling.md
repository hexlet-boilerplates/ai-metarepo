# Инструменты

Документ читается перед правкой `mise.toml`, `hk.pkl`, `sgconfig.yml` и задач.

## mise

`mise.toml` объявляет инструменты (`ghorg`, `ast-grep`, `gh`, `hk`, `pkl`), задачи лежат файлами в `mise-tasks/`. Свежий клон ставится двумя командами, `mise trust` и `mise run setup`. Доверие нужно, потому что конфиг mise может запускать код.

Версии в `mise.toml` заданы как `latest`. Для демонстрации нужна рабочая связка на сегодня. Если метарепозиторий начнёт выпускать релизы, версии стоит зафиксировать, иначе два разработчика получат разные результаты проверок.

## Git-хуки

Хуки ставит `hk` командой `hk install`, шаги описаны в `hk.pkl`. Установка идёт в конкретный репозиторий, общий `core.hooksPath` не используется, потому что он переносит хуки одного репозитория на другие.

Хук метарепозитория работает только в его git. У клонов в `repos/` свой `.git` и свои хуки, поэтому коммит внутри клона наш хук не запускает. Это граница, на которой общая проверка клонов держится на задаче `mise run check`, а не на хуке.

Шаги в `hk.pkl`:

| Шаг | Когда срабатывает | Что делает |
| --- | --- | --- |
| `ast-grep-rules` | правится `ast-grep/` или `sgconfig.yml` | `ast-grep test --skip-snapshot-tests` |
| `mise-tasks` | правится `mise-tasks/` | `bash -n` по каждому файлу |

Проверка самого файла: `hk validate`. Запуск без коммита: `hk check --all`.

## ast-grep

Правила в `ast-grep/rules/`, тесты в `ast-grep/rule-tests/`, конфиг `sgconfig.yml`. Запуск по клонам идёт с `--no-ignore parent`, причина в [ast-grep/README.md](../../ast-grep/README.md).

Правило добавляют скиллом `add-ast-grep-rule`. Серьёзность `error` роняет `mise run check`, `warning` только печатает. Правило по умолчанию стоит делать `error`, а исключения выносить в `ignores`, иначе находки копятся и их перестают читать.

## ghorg

Клонирует репозитории организации. Конфиг `.ghorg.conf.yaml`, запуск через `mise run clone`, токен берётся из `gh auth token`. Что можно и нельзя делать, описано в [repos/README.md](../../repos/README.md).

## Что не подключено

Нет CI и релизного процесса, метарепозиторий ничего не публикует. Нет проверки Conventional Commits хуком, правило записано в `AGENTS.md` и подтверждается человеком при коммите.
