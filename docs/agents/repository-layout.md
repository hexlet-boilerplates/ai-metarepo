# Раскладка и запуск агента

Документ читается до клонирования, до выбора каталога запуска агента и при разборе «агент не увидел правило».

## Раскладка

```text
ai-metarepo/            git метарепозитория
├── AGENTS.md           правила для агента
├── docs/, specs/       документы, решения, контракты
├── ast-grep/           правила, которые проверяются кодом
├── mise-tasks/         задачи
└── repos/              в .gitignore
    ├── nodejs-package/        свой git, своя ветка
    ├── typescript-package/    свой git, своя ветка
    └── ...
```

Метарепозиторий и клоны это разные git-репозитории. Команда `git status` в корне не показывает правок в `repos/`, а коммит в корне не включает файлы клонов. Поэтому правило `AGENTS.md` требует выполнять git внутри каталога репозитория, которого касается задача.

## Откуда запускать агента

Запускай из корня метарепозитория. Что при этом видит каждый инструмент, зависит от того, как он ищет `AGENTS.md`. Ниже поведение по документации Claude Code и по исходному коду Codex на 23 октября 2026 года. Проверяйте его на своей версии, оно менялось.

**Claude Code.** При запуске читает `AGENTS.md` рабочего каталога и всех каталогов выше. Файлы подкаталогов загружаются лениво, когда агент читает файл в этом подкаталоге. Из корня метарепозитория это значит, что `AGENTS.md` метарепозитория есть на старте, а `AGENTS.md` клона появляется, когда агент открыл файл в клоне. Настройки `.claude/settings.json` берутся только из каталога запуска. Если запустить Claude Code в клоне, он поднимется по каталогам и найдёт `AGENTS.md` метарепозитория, но настройки метарепозитория не применятся. Чтение `AGENTS.md` без `CLAUDE.md` появилось в версии 2.1.277, источник [документация Claude Code](https://code.claude.com/docs/en/memory#agents-md).

**Codex.** Поднимается от рабочего каталога до ближайшего `.git` и дальше не идёт. Из корня метарепозитория он читает только `AGENTS.md` метарепозитория, файлы клонов подтягиваются, когда рабочий каталог оказывается внутри клона. Если запустить Codex внутри клона, у клона свой `.git`, и `AGENTS.md` метарепозитория в контекст не попадёт. Вывод сделан по исходнику `agents_md.rs` (rust-v0.164.0), в документации явной фразы про вложенные клоны нет.

**Что из этого следует.** Правила, которые должны действовать на все клоны, нельзя доставлять только через `AGENTS.md` метарепозитория, потому что Codex в клоне его не увидит. Для них есть проверка кодом (`mise run check`), она не зависит от того, прочитал ли агент файл. Правила одного клона лежат в его собственном `AGENTS.md`.

## Рядом лежащие каталоги

Каталог `--add-dir` у Claude Code даёт доступ к файлам, но `AGENTS.md` из него не читается. Поэтому клоны лежат внутри метарепозитория, а не рядом с ним.

## Клонирование

Клонирует `mise run clone`, список репозиториев лежит в `[bootstrap.repos]` в `mise.toml`. Подробности в [../../repos/README.md](../../repos/README.md), причина выбора в [ADR 0004](../adr/0004-clones-via-mise-bootstrap-repos.md).

Версия клона равна моменту клонирования. Если нужна воспроизводимая пара «спека плюс код на конкретных коммитах», этой раскладки недостаточно, нужны submodules или манифест с хешами.

## Чужие правки

Клоны могут содержать правки другого человека или другой сессии агента. Перед правкой выполни `mise run status` и посмотри `CHANGED`. Не делай `git add .` в клоне, добавляй файлы по именам.
